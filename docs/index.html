looped aikitchen - a looped transformer lab

looped.aikitchen.cc github

NVIDIA released its looped model Dory1.0-4B with no tech report. This lab rebuilds the research the market already knows from smaller looped models, runs the new kid locally in Docker, and measures loop counts on real GPU.

Status: the stack is running. A looped llama.cpp build of PR 30306, a 3.42 GiB GGUF on an RTX 4070, loop-count variants from GGUF metadata surgery, a smoke test, and a replicated 36 task synthetic loop eval.

What the lab learned so far

The one sentence version: going from 1 to 2 loops buys the most accuracy (+15 points on a 72 question combined eval) while deeper loops mostly just cost speed. Stack programs are the loop sensitive kind (5/24 at one loop, 11/24 at two); easy arithmetic almost never needs a loop.

Two independent data draws at temperature 0, 12 GiB GPU. The same accuracy buys speed: throughput falls from about 110 tok/s at one loop to 42-47 at four.

How the loop knob was built

The dory support in llama.cpp (PR 30306, still open) reads the loop count from GGUF metadata only (dory.num_loops, uint32), no CLI flag. The lab parses the exact on disk layout, finds the field by scanning all 44 metadata KVs (this GGUF is v3 with no alignment padding), copies the file and rewrites a single uint32, so weights are byte identical and variants are cheap: 1, 2 and 3 loop clones of the official 4 loop GGUF.

Serving itself is its own story: the official llama.cpp v0.8.0 image says unknown model architecture: 'dory', so the lab builds its own CUDA image pinned to the PR head.

Run it

The lab expects a pixi workspace named loop, a CUDA host with about 8 GiB free VRAM, and a read-only HF token in .env.

  1. python tests/make_dory_loop_variants.py --cycles 1 2 3 - the loop count clones
  2. docker build -t loop-llama-cpp:pr30306 docker/loop-llama-server and docker compose -f docker/loop-llama-server/compose.yaml up -d - serve on port 8777
  3. python tests/test_dory_smoke.py - 3 checks against the live server
  4. python tests/test_loop_evals.py --cycles 1 2 3 4 - borrow the GPU per variant, score, hand it back

Notes

Everything here ran on one RTX 4070 and is reproducible from a clean clone. The model license is NVIDIA Open Model, the local code is for learning, and the results are the lab's own, not NVIDIA's.

  • No cloud model and no API key. The only network calls at runtime are the local llama.cpp server and the read-only HF Hub for downloads.
  • Static page only. Everything dynamic runs in the loop- prefixed Docker stack; the GUI, when it exists, builds into gui/, never here.
